# 2026-08-24 — Store mutation acceptance

## Store acceptance

- Ran the database-aware store sweep after `dc94712` against a disposable PostgreSQL 16
  container with `MUTANT_TEST_TAGS=integration` and `DATABASE_URL`.
- The first sandboxed attempt failed closed at the neutral calibration control because loopback
  sockets were denied. The host-loopback rerun calibrated correctly.
- Baseline rerun: 113 candidates, 90 killed, 0 invalid, 23 survivors. This improved the previous
  pre-`dc94712` result (55 killed, 58 survivors) but was not acceptance.

**HARM:** A green store suite could still allow the ledger to lose exclusivity, accept unsafe path
relationships, ignore a lost lock, leak database resources, present live transaction wrappers as
closed (or panic on closed wrappers), and permit mutation of the append-only event ledger.

**ROUTES to that harm:**

1. Close could return without releasing a live `flock`; a replacement lock-path inode was not
   distinguished from a missing path; and a deep DataDir/RuntimeDir overlap could be accepted.
2. An explicitly correct derived LockPath could be rejected, while the informational lock record
   could be omitted.
3. `Store.usable` could ignore `ErrLockLost`, allowing the next operation to proceed after
   dispossession.
4. Failed URL parsing, ping, embedded startup, or migration could take inconsistent cleanup paths
   and strand the lock/server.
5. Valid `Tx`, `Row`, and `Rows` wrappers could report `ErrClosed`; empty wrappers could panic;
   and `Rows.Close` could fail to close live rows.
6. Either `||` in the UPDATE/DELETE/TRUNCATE guard could become `&&`. The existing test did not
   detect this because its failure branch returned the unexpected `nil` error, falsely passing.
7. A redundant second path-overlap check made one predicate mutation equivalent and encouraged a
   fragile positional allowlist entry.

- Added route-level unit and integration tests, fixed the false-positive ledger-write assertion,
  made lock-record publication sequential and fail-closed, made failed-open cleanup uniform, and
  removed the redundant overlap check.
- Intermediate sweep: 109 candidates, 108 killed, 0 invalid, 1 equivalent survivor. The redundant
  route was removed rather than declared.
- **Acceptance sweep: 107 candidates, 107 killed, 0 invalid, 0 survivors.** Calibration was green.
  `docs/allowed-survivors.txt` therefore needs no store entry. Store mutation acceptance is closed.
