# 2026-08-24 — Store mutation acceptance

## Store acceptance

- Ran the database-aware store sweep after `dc94712` against a disposable PostgreSQL 16
  container with `MUTANT_TEST_TAGS=integration` and `DATABASE_URL`.
- The first sandboxed attempt failed closed at the neutral calibration control because loopback
  sockets were denied. The host-loopback rerun calibrated correctly.
- Baseline rerun: 113 candidates, 90 killed, 0 invalid, 23 survivors. This improved the previous
  pre-`dc94712` result (55 killed, 58 survivors) but was not acceptance.

**HARM:** A green store suite could still allow the ledger to lose exclusivity, accept unsafe path
relationships, ignore a lost lock, leak database resources, present live transaction wrappers as
closed (or panic on closed wrappers), and permit mutation of the append-only event ledger.

**ROUTES to that harm:**

1. Close could return without releasing a live `flock`; a replacement lock-path inode was not
   distinguished from a missing path; and a deep DataDir/RuntimeDir overlap could be accepted.
2. An explicitly correct derived LockPath could be rejected, while the informational lock record
   could be omitted.
3. `Store.usable` could ignore `ErrLockLost`, allowing the next operation to proceed after
   dispossession.
4. Failed URL parsing, ping, embedded startup, or migration could take inconsistent cleanup paths
   and strand the lock/server.
5. Valid `Tx`, `Row`, and `Rows` wrappers could report `ErrClosed`; empty wrappers could panic;
   and `Rows.Close` could fail to close live rows.
6. Either `||` in the UPDATE/DELETE/TRUNCATE guard could become `&&`. The existing test did not
   detect this because its failure branch returned the unexpected `nil` error, falsely passing.
7. A redundant second path-overlap check made one predicate mutation equivalent and encouraged a
   fragile positional allowlist entry.

- Added route-level unit and integration tests, fixed the false-positive ledger-write assertion,
  made lock-record publication sequential and fail-closed, made failed-open cleanup uniform, and
  removed the redundant overlap check.
- Intermediate sweep: 109 candidates, 108 killed, 0 invalid, 1 equivalent survivor. The redundant
  route was removed rather than declared.
- **Acceptance sweep: 107 candidates, 107 killed, 0 invalid, 0 survivors.** Calibration was green.
  `docs/allowed-survivors.txt` therefore needs no store entry. Store mutation acceptance is closed.

## Task 4 — Git connector implementation (author-ready, not accepted)

- The imported migration corpus claimed Task 4 was in Round-3 remediation and named committed
  verdict/code paths. Repository inspection proved those artifacts never existed in this Git
  history: only the parent connector SPEC had been imported, and it was misplaced at the child
  `gitcmd/SPEC.md` path. No local object, reflog, branch, tag, or remote ref could recover code or
  verdicts. Task 4 therefore started honestly from the committed contract rather than pretending
  the historical verdict was evidence about this implementation.
- Restored the parent SPEC to `internal/connector/git/SPEC.md`, wrote the child gitcmd SPEC before
  code, implemented the pure connector and standard-library Git adapter, and added real-repository
  fixtures for amend, two-commit rebase, branch switch, detached/tag history, older commit dates,
  shallow/grafted/replaced history, hostile paths/content, ref exclusions, and corrupt refs.

**HARM:** A green Git connector could permanently append incomplete or contradictory commit facts,
silently omit real rewritten/older history, fabricate decision citations, ingest stash/notes as
product history, or report a broken repository as a successful empty sync. Because the ledger is
append-only, a wrong payload for one SHA cannot be repaired in place.

**ROUTES to that harm:**

1. Shallow boundaries, legacy `.git/info/grafts`, and replacement objects can change ancestry and
   make a boundary commit's whole tree appear to be its changed files.
2. A date watermark can skip rebased, fetched, or deliberately older-dated commits; a hand-built
   ref scope can omit tag-only, non-checked-out branch, or detached-HEAD history.
3. Bare `--all` can ingest stash, notes, or replacement refs; prefix exclusions can accidentally
   drop legitimate names such as `refs/stashed`.
4. Greedy and lazy citation regexes can each fabricate a different prefix. Citations now resolve
   only when an exact `docs/decisions/<id>.md` exists in the observed commit's own tree.
5. Delimiter-shaped commit text, quoted/hostile filenames, scalar-placeholder swaps, or trimming
   can misattribute fields while producing valid JSON.
6. Git can ignore a corrupt loose ref while `rev-list --all` exits successfully; explicit loose-ref
   validation is required to keep broken distinct from empty.
7. Incorrect append counts, swallowed append errors, or a cursor used as an input can make a partial
   or skipped sync look complete.

- The first real-repository suite exposed two live assumptions before mutation: this environment's
  Git lacks `git init -b`, and `rev-list --all` stayed successful with a corrupt loose ref. Fixtures
  were made version-compatible; product code now validates loose refs.

- Final gitcmd sweep: 60 candidates, 60 killed, 0 invalid, 0 survivors.
- First combined parent+child sweep: 77 candidates, 75 killed, 0 invalid, 2 survivors. Direct tests
  closed every uninitialized-connector guard route.
- **Final combined sweep: 77 candidates, 77 killed, 0 invalid, 0 survivors.** Calibration passed;
  no allowlist entry was needed. The mechanical Task-4 DoD and `make check` are green author-side.
- **Not accepted:** Build Law 9 requires a non-author adversarial verdict committed on receipt.

## Task 4 — current Round 1 independent verdict

The frozen `3470e60` implementation received `NEEDS_WORK`; the verdict is committed verbatim at
`docs/verification/verdicts/task4-current-round1.md` before remediation.

**HARM:** The connector can append incomplete commit facts or a fabricated citation, and can report
a broken repository as a successful sync. It can also collapse two distinct Git path byte strings
to one JSON string. Because event identity binds to payload content in an append-only ledger, those
observations cannot be repaired in place.

**ROUTES to that harm:**

1. A loose ref, packed ref, or detached HEAD can contain a syntactically valid object id whose
   object is absent; `rev-parse` can validate the spelling while history listing omits the object.
2. Different non-UTF-8 path byte sequences both become Unicode replacement characters during the
   Go string to JSON conversion, destroying Git path identity.
3. Taking only `path.Base` admits `docs/decisions/archive/VD-*.md` as though it were the direct
   decision path named by the contract.
4. `diff-tree` without a defined merge mode emits no paths for merge commits, so a real first-parent
   tree change is recorded as an empty `FilesTouched` list.
5. `--reverse --date-order` preserves ancestry and therefore is not the strict committer-date sort
   the parent interface prose claimed; the prose overstated a non-correctness convenience.
6. A typed-nil pointer stored in the `Repo` interface passes the constructor's plain nil check and
   creates a connector that fails only when used.

Remediation refuses missing targets for loose refs, packed refs, and detached HEAD; refuses
non-UTF-8 path streams; requires decision files to be direct children of `docs/decisions`; defines
every non-root commit's file set as its first-parent tree delta; corrects the ordering prose; and
rejects typed-nil pointer repositories at construction. Each route has a discriminating test; the
three missing-object cases exercise both `Commits` and `Tips`.

- `make check` is green after the remediation.
- gitcmd mutation sweep: **70 candidates, 70 killed, 0 invalid, 0 survivors**.
- combined parent/child mutation sweep: **88 candidates, 88 killed, 0 invalid, 0 survivors**.
- Task 4 remains open until a non-author reviews the frozen remediation and returns an ACCEPTABLE
  verdict; author-side green is not acceptance.
