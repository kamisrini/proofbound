## block-generated-edit scope fix + deferrals SIGPIPE + dep hardening (commit `f387689`)

Picked up the first of the three unblocked slices named in the prior Resume. All three changes
below carry independent non-author verdicts (Law 9); both verdict rounds returned ACCEPTABLE.

- `.claude/hooks/block-generated-edit.sh`: the scope-blind `rg -q '@generated'` rule (blocked ANY
  file containing the string — CLAUDE.md, gates.md, journals, generator scripts, and the hook
  itself) is replaced by the Law 1 marker rule: block only a file whose header carries
  `@generated by <cmd>` — first line not a shebang AND the marker within the first 5 lines. This
  separates genuinely generated artifacts (marker at lines 1–3) from two classes that legitimately
  contain the string: prose/governance files that MENTION it (never in the `@generated by` form) and
  hand-authored generator scripts that EMIT it deeper in their body (shebang-first). Verified against
  all 23 real `@generated` files: 10 generated blocked, 13 hand-authored allowed, zero false
  positives/negatives.
- The broken hook had DEADLOCKED its own repair: the Write/Edit channel was blocked by the live hook
  (its own file contains `@generated`) and the Bash channel was denied by the self-modification
  classifier. The owner applied the staged fix by hand (`cp` from scratchpad). The corrected hook is
  self-consistent — shebang-first, so it no longer blocks itself.
- Law 3 hardening (reviewer finding F2): the hook guarded `jq` but used `grep`/`head` unguarded, so a
  missing matcher dependency failed OPEN on a generated file. Added
  `command -v grep && command -v head || exit 2`, and the rewrite dropped the non-prereq `rg`
  dependency (Law 8 prereqs are bash/git/jq) for coreutils grep/head, reducing real fail-open risk.
- `scripts/tests/claude-hooks.test.sh`: rewrote the block-generated-edit self-test with calibrated
  controls spanning both true-positive classes (doc header, `#`-comment lock header) and both
  false-positive classes (prose/governance, shebang-first generator script), plus a fail-closed
  control. That fail-closed control was initially INERT — it stripped PATH so far that the fake jq
  failed first (its own `#!/usr/bin/env bash` shebang needs bash; its body needs sed), so the hook
  exited before reaching the dependency guard. Corrected by supplying every transitive dep
  (bash, cat, git, sed, head) and omitting only grep, against a generated fixture; proven live by
  reconstructing the guard-less hook — the self-test FAILS without the guard (exit 0/ALLOW) and
  PASSES with it (exit 2/BLOCK).
- `scripts/tests/deferrals.test.sh`: `scripts/deferrals.sh --open | grep -Fq …` died of SIGPIPE
  (exit 141) — `grep -q` closes the pipe on first match, the producer dies, and `pipefail` promotes
  141 to the pipeline's exit. Deterministic (5/5 at HEAD). Replaced with
  `out=$(producer); grep -Fq … <<<"$out"`, which removes the pipe while preserving the
  producer-exit-status assertion under `set -e`. This self-test was failing `make hooks-test`
  alphabetically BEFORE p6-task8, so the prior Resume's "RED at p6-task8" was understated — the real
  first red point was deferrals.
