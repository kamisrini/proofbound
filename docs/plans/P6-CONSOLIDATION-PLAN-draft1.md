## Why a census, not a gap list from memory

The author of this plan cannot see the repository. The corpus's own law — a claim of "verified against X" must be a loop over X, never an enumeration from memory — therefore forbids this plan from asserting the gap list. Instead, Task 0 generates the authoritative gap inventory MECHANICALLY from the repository itself. The categories below are pinned scan classes, each with a closing Definition of Done; they are seeds, not bounds — a gap discovered outside every category still enters the census, and a category that returns zero rows simply closes free. The 2026-09-12 vision-progress assessment is this phase's motivating exhibit: commit it under `docs/verification/` if it is not already committed, and let the census confirm or refute each of its 🟡 rows mechanically.

## Task 0 — The debt census (this phase's own spec)

Produce `docs/plans/p6-census.md`, committed, generated by mechanical sweeps — each sweep a script or command whose invocation is recorded beside its results:

- **C1 — Doc truth.** Every mechanism claim in `README.md`, `ROADMAP.md`, `notes/state.md`, and the plans (a named make target, script, gate, or check) is cross-checked against what exists on disk. A described-but-absent mechanism, or an existing-but-undescribed one, is a census row. This is the "imported prose describes checks that are absent" caution from the P5 handoff, made a loop.
- **C2 — Gate estate.** Every check named anywhere is present, self-tested, and runs where its registry row says it runs. Every advisory row's expiry is enumerated. Known named debts to confirm or refute: `make backup`, a complete `make short` inner loop, state-freshness, skip-lint, prescription-lint, full historical invariant-citation resolution.
- **C3 — Acceptance coverage.** Per kernel package: mutation-sweep status and a non-author verdict bound to the CURRENT code revision (a verdict for a superseded revision does not count). Packages behind the bar are census rows.
- **C4 — Connector reality.** Per connector: live-source acceptance status (the sessions connector was accepted on synthetic fixtures — that is a row by definition), every deliberately declared narrowness (each kept-with-recorded-reason or widened), and source/tenant separation semantics verified by test where more than one repo or provider is configured.
- **C5 — Event-universe re-proof.** Every P1–P4 mechanism (projection rebuild, `proofbound verify`, twin replay, gate evaluation) proven over the FULL current event universe, including the P5 kinds (`business_decision.recorded`, `requirement.recorded`, `change_intent.recorded`, `requirement.reviewed`) and the provider sources. Any mechanism that predates a kind and carries no proof over it is a census row. This is the highest-risk category: the twin and the oldest projections predate intent provenance.
- **C6 — Intent self-coverage.** Measured over Proofbound's own repository since P5 acceptance: the percentage of behavior-changing commits carrying a valid `Intent:` trailer; every ACTIVE requirement obligation lacking a non-author `VERIFIABLE` review verdict; the chain state of each of Proofbound's own deliveries.
- **C7 — Measurement debt.** The P5 plan mandated measurements and falsifier evaluations during self-hosting; each is either collected-and-committed or a census row. Gate canary evidence recorded where the gates doc claims it.

**Census DoD (mechanical):** the census file is committed; every row is classified exactly one of `close-in-P6`, `defer-to-P7 (decision-recorded, with the deferral reason)`, or `wontfix (decision-recorded)`; zero unclassified rows; `ROADMAP.md` gains the P6 section (text at the end of this plan) in the same change.

## Non-goals — the width this phase refuses

- No behavior locks, witnessed regeneration, or natural-language-to-test machinery.
- No production-shaped twin: no traffic replay, chaos, surrogates, or confidence-scored futures.
- No cryptographic signing, verifier identities, portable warranties, or marketplace.
- No governor, policy envelopes, credential control, or autonomy ratchet.
- No end-user UI and no external customer delivery boundaries.
- No new event kinds and no new providers beyond Task 8's founder-gated conditional.
- No QA-ladder level jumps: this phase deepens L1–L2 foundations; it does not attempt L3+.

Anything on this list found inside a task's execution is scope creep; stop and re-read the doctrine line.

## Measurements and falsifiers for this phase

Measurements: census burn-down (rows opened vs closed, per category, weekly); intent self-coverage percentage; witnessed-run coverage percentage; advisory-row count (target zero); packages under the acceptance bar (target all).

Falsifiers — evaluate honestly, act on any that fires:

1. Census rows keep appearing in a category after two full sweeps — that category's scan is inert or scope-blind; fix the scan before closing more rows.
2. The majority of closed rows are doc-truth edits and the founder-set effort ceiling is reached — depth was already adequate; stop early, record the position, and move to P7 planning. (The ceiling is a founder ratification input; consolidation must not decay into gold-plating.)
3. The requirement-review sweep rubber-stamps — near-zero findings across many reviews while downstream `INCONCLUSIVE` outcomes persist (carried from P5, falsifier 7).
4. Task 5's canary shows the closed path rule misclassifies more than a founder-set fraction of history — the applicability rule is wrong; re-ratify the rule, do not enforce a misfiring gate.
