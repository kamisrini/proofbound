## Findings
- **F1 (MED).** kernel/internal/cli/workspaces_test.go (TestAsOfAudit) and timeproof.go:asOfCompute — CLI-INV-50's central claims (a detached worktree at the commit, its own record built only from it, nothing after the commit visible, worktree removed, refused with DATABASE_URL) are mapped to a test that replaces `s.asOf` with a stub. Nothing exercises asOfCompute, so a leak (for example computing against HEAD), a leftover worktree or a missing refusal would not fail any test. Fix: add a non-tagged test that builds a small repo with a commit after the chosen one, calls asOfCompute (or at least its worktree add/remove and the DATABASE_URL refusal with a stubbed `sync`), and asserts the later commit is absent from the result and `git worktree list` is back to one entry; or restate the invariant as not test-covered and add a gates.md row with an expiry.
- **F2 (MED).** kernel/internal/cli/timeproof.go:130 — `_ = runCommand(ctx, commandSyncAll, ...)` discards the sync error, and the result is then cached for the life of the server (`asOfMem`). A failed or partial sync (timeout, cancelled request, sdd error) yields an audit built from an incomplete record (for example gates read as NO REVIEW), presented under the banner "exactly as it stood then", and wrong forever. Fix: return the error (or carry it as a visible "record partly built" notice like SyncError) and do not cache a result whose sync failed or whose ctx was cancelled.
- **F3 (MED).** kernel/internal/cli/timeproof.go:127 — `gitRun` uses the user's hooks, so a GET of `/audit?asof=` runs the repository's post-checkout hook with the temp path, and writes `.git/worktrees/` metadata. A hook that fails makes the time rail fail; one that has side effects acts on a read request. If the request context is cancelled mid-add, the registration can remain (git worktree prune is never run). Fix: `git -c core.hooksPath=/dev/null worktree add ...`, and run `git worktree prune` after a failed add/remove.
- **F4 (LOW).** workspaces_test.go TestBrowserProofData — it proves the data and a Go re-implementation of the browser canonical form verify, not app.js itself, and its helper `jsStringify` differs from JSON.stringify (Go's encoder escapes U+2028/U+2029 even with HTML escaping off; JS does not). The test cannot fail if app.js `canonical`, `fromHex` or the key/tag checks break. The test also has no control character or U+2028 case. Fix: record that the JS is exercised only by the owner's manual run, or add a small node-based check, and add U+2028 and a control character to the reason.
- **F5 (LOW).** ui.go (viewAsOf/asOfMem) — the cache is unbounded (every commit of the period, each a full ledgerView). "Nothing can be signed while a past moment is shown" is page-only: the POST acts still operate on now if called. Review files without a `.sig` are silently omitted from the Review signatures column instead of shown as unsigned. `sync all` in the temp checkout also reads local, non-git sources (sessions, checks) that are not time-bounded by the commit, so "then" can differ from "now" for reasons other than the record.
