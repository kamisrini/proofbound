## Status
NEEDS_WORK: one HIGH and three MED. Checked and sound:
- The record is read from the commit's first parent only, never from the commit or HEAD; a waiver written in the same commit does not count (tested). Keys are the parent's (`declaredKeys(parent)`), so a key added in the waived commit itself cannot sign. `verifyRecord` binds `by` to the key declared under that name and to its fingerprint, requires canonical bytes and only the schema's fields, and the file name must equal `id`. Non-`.json` entries, subdirectories, ids outside the regex and symlinks (their blob is the link target, which fails verification) are skipped or refused.
- The listing is `ls-tree` of the parent tree, so the working tree is never read. Paths are matched against every non-housekeeping path from the same `-z --no-renames --cc` diff that C2 already uses, so a rename needs both its old and new path covered, and a clean merge has nothing to waive.
- `check`, `warranty bundle` and the Audit room all classify through the one `uncoveredCommits`, so the same commits are WAIVED everywhere. The headline suffix is appended in every branch (all branches end in `)`), a waived commit never causes NOT WARRANTED, and exit codes are unchanged otherwise. `--require-claims` with only waived commits still reads NO CLAIMS and fails.
- Escaping: plain output goes through `printableUnit`; the check Markdown and VERIFY.md cells go through `mdCell`; the Audit room uses html/template; the badge text is HTML-escaped. `by` is a key name restricted to the key-file regex.
- `index.json` omits `waived` when empty (nil slice with `omitempty`), so a bundle without waivers is byte-identical (tested). `init` adds only the `!.proofbound/waivers/` line, and `waiver sign` tells an older project how to commit an ignored waiver.
- `waiver sign` validates id, patterns, reason, date format, past and 90-day bounds, requires a single declared local key, writes O_EXCL and never commits; the parser refuses repeated `--reason`/`--expires`, unknown flags and a flag in the id position (all tested).
- The hook reads the author with the hook's own environment (so `-c user.name` and `GIT_AUTHOR_NAME` are seen, tested), parses agent co-authors more widely than the trailer-only check (stricter, so safe), and with no HEAD falls back to the existing refusal.

## Findings
- **F1 (HIGH).** kernel/internal/cli/waiver.go:197-207 with oversight.go:139-158 (`independence`) and check.go:199-210. Independence compares the waiver's key NAME with `KeyName(git author name)`, a declared agent name, and the commit signer's name; nothing ties a key to a person. Three confirmed ways the author's own waiver counts: (a) no forgery at all: Alice ran `keys init --name alice` (the documented option), her git `user.name` is "Alice Smith", so `KeyName` gives `alice-smith` and her own waiver on her own unsigned commit reads `WAIVED  waived by alice` in check (the deferral's done-when, "an author-signed waiver is refused", fails in an ordinary setup); (b) the author declares her same public key a second time as `.proofbound/keys/reviewer.pub` and hand-signs a record with `by: reviewer` (verifies, WAIVED); (c) the same with a fresh sock-puppet key committed in the same pull request before the waiver, since the parent's keys are trusted whatever their age. In (b) and (c) `proofbound check`, the PR gate, shows only "waived by reviewer"; the new key appears only in Audit C6, and only when it is in the viewed period. Fix: (1) in check and bundle, verify waivers only against keys declared both at the range base and at the parent, so a pull request cannot mint its own approver (the attestation rule already uses the base's keys); (2) compare by key, not by name: refuse when the waiver's public key equals the key declared under `KeyName(author name)`, under `KeyName(author e-mail local part)`, under any agent name, or the verified commit signer's key, so a second name for the same key and a `--name` that differs from `user.name` are both caught; (3) state the remaining limit (an unsigned commit's author is self-declared) in spec §2, or require a waived commit to carry a verified signature by a key other than the waiver's. Add tests for (a), (b) and (c).
- **F2 (MED).** kernel/internal/cli/audit.go:495-503 (`commitInfos`, used by check.go:209) and waiver.go:286-290 (the hook). Only co-authors whose name matches an agent marker enter the independence rule; human co-authors are dropped. Confirmed: dev commits `vendor/a.c` with `Co-authored-by: approver <approver@example.com>` and approver's waiver makes it WAIVED. The spec's principle is "signed by someone who did not write the change"; a co-author wrote it. Fix: for waivers, pass every `Co-authored-by` name (agent or not) as a writer, in both check and the hook, and add a test.
- **F3 (MED).** kernel/internal/cli/waiver.go:159-161 and :209. Expiry is judged against the commit's committer date, which the committer sets freely, and an expired waiver stays in every later parent until someone deletes it. Confirmed: a waiver that expires tomorrow covers a commit made with `GIT_COMMITTER_DATE` set a year back (WAIVED). So once a waiver exists, its expiry binds only honest committers, and spec decision 1 ("no waiver is permanent") does not hold against the author it is meant to bind. The spec's rationale ("condition 1 is the stronger fact") says when the waiver began, not that it has not ended. Fix: judge against an effective date that cannot be pushed back below facts the author does not control: at least max(committer date, the day of the waiver's signed `at`), and in check and bundle also the range base's committer date (the base is on the protected branch). Say in the check line which date was used, as §2 already promises. Add a backdating test.
- **F4 (MED).** kernel/internal/cli/waiver.go:197-211. The 90-day bound and the date format are enforced only by `waiver sign`; verification accepts any `expires` string and compares it as text. Confirmed: a hand-signed record with `expires: 9999-12-31` (or any string that sorts after a date, for example `z`) is valid forever, and `at` is never checked either. Owner decision 1 makes "never permanent" a property of the waiver, and the authoritative check is where it must hold. Fix: in `waiversAt`, require `expires` to parse as `YYYY-MM-DD` (round-trip), `at` to parse as RFC 3339, and `expires` to be at most 90 days after `at`'s day; otherwise the waiver "does not verify". Add a test with a hand-signed long-lived record.
- **F5 (LOW).** kernel/internal/cli/waiver.go:87-91 (`checkAreaPattern`). A waiver may cover `**` (confirmed: `waiver sign all --path '**'` succeeds and then waives any code change for 90 days), or `*/`, which defeats "limited to named paths". The signer is still independent and the reason is shown, so this is a widening by consent, not a forgery. Fix: refuse at signing and at verification a pattern with no literal segment (only `*` and `**` segments).
- **F6 (LOW).** kernel/internal/cli/waiver.go:168-214 (spec §4 "no revocation other than not in the parent"). Deleting a waiver is its only revocation, but anyone can restore the same bytes from history and it verifies again until it expires (confirmed: sign, delete, restore by the author, use: WAIVED). The record is also not bound to a repository, so a waiver signed by a key holder declared in two repositories replays across them. C6 lists the restore commit, and expiry bounds both. Fix: bind the record to the repository (for example its root commit) and treat a waiver path that was ever deleted in the parent's first-parent history as revoked; or record the limit in spec §4.
- **F7 (LOW).** kernel/internal/cli/waiver.go:267-293 (`stagedWaived`). The hook never knows the commit's signer, so with `keys git-sign` configured, Alice (key `alice`, `user.name` "Alice Smith") passes the hook with her own waiver (confirmed), while check, which sees her verified signature, refuses it. The hook lets through what check refuses in the setup Proofbound recommends. Fix: in the hook, also treat this machine's declared key (`localActor`) as a writer of the commit: the waiver's signer should be on another machine. F1 (2) also removes most of this gap.
- **F8 (LOW).** kernel/internal/cli/audit.go:601, :588, :272 and uikit/audit.html:195. Users with no waivers see more than the listed changes: the C2 held count now reads "claim a spec, change no code or are waived", the C2 basis and the C6 question, command and basis gained waiver text, and the population bar's aria-label says "0 waived". None breaks an attestation (`readAttestations` does not recompute the transcript digest) but each changes the transcript. Fix: add the waiver words only when a waiver exists (as the legend already does), or list these changes in the spec's compatibility note.
- **F9 (LOW).** kernel/internal/cli/waiver_test.go:247-271. TestAuditWaived calls `uncoveredControl` with hand-made lines and `trustPaths` on one commit; it never runs `computeAudit`, so CLI-INV-59's "classes a waived commit `waived` (C5 counts it)" is not proven, and a bug in the class or count loops would pass. TestWaiverCovers passes the agent list by hand, so agent detection from a real `Co-Authored-By` trailer (the check path) is untested too. Fix: add one `computeAudit` run on a waived repository asserting the class, `Counts.Waived`, the C2 state and the C5 evidence, and one check case where the signer appears only as an agent co-author trailer.
