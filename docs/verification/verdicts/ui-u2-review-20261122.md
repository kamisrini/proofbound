## Findings
- **F1 (MED).** kernel/internal/cli/ui.go:216-221, 254-262 — "agents read, people act" is not kept. The bearer token in `.proofbound/ui.json` is the same token the `?k=` login accepts, which sets the HttpOnly cookie. Any process that can read ui.json (an agent in the same account) does `GET /?k=<token>`, takes the cookie, then POSTs `/act/review-seal` with a self-set Origin header and seals a review as the human's declared key, for a commit that agent wrote. `TestAgentNext` only checks that a bearer POST gets 401, not this route. Fix: write a separate read-only token to ui.json that is accepted only as a Bearer on GET and never by `?k=`; add a test that `?k=<ui.json token>` returns 403.
- **F2 (MED).** kernel/internal/cli/gitsign.go:73-76 with warranty.go:415 — the OpenSSH private key is created with mode 0644 by writeExclusive and only chmodded to 0600 afterwards, so it is world-readable for a window (and permanently if the chmod fails, since the error leaves it behind). Fix: open the file with 0o600 (a dedicated exclusive writer with a mode argument), and remove the file if the chmod or `.pub` write fails. Test the mode right after creation or with a failing chmod.
- **F3 (MED).** kernel/internal/cli/gitsign.go:90-94 — `git config --local` in a linked worktree writes the shared repository config, so with the repo's worktree-per-agent model each `keys git-sign` run replaces `user.signingkey` for every worktree. Agent B's commits are then signed as agent A and C9 reports them verified under the wrong name, which also feeds the signer exclusion in C8. Fix: use `git config --worktree` (enabling `extensions.worktreeConfig`) or refuse to run in a linked worktree; add a worktree test.
- **F4 (MED).** kernel/internal/cli/workspaces.go:165-176 — the "same words" rule can hide a later negative finding. If revision 1 was SATISFIED, revision 2 was NOT_SATISFIED, and revision 3 has the same words as 1 and no verdict yet, `provenBefore` still holds the revision-1 proof and the promise reads PROVEN with the old reviewer. The latest outcome in ledger order should win. `TestPromiseStates` has no intermediate NOT_SATISFIED. Fix: record the latest earlier outcome per change intent and obligation and carry a proof forward only if that is SATISFIED; add the case to the fixture.
- **F5 (LOW).** kernel/internal/cli/oversight.go:84-91 — `%G?`=G with a GPG signature reports the signer's uid as `%GS`; a uid that equals a declared key name would read as verified for that key. It needs a trusted key in the auditor's keyring, but the code should require an SSH signature (for example check `%GF`/the key fingerprint against the declared key). Also, a key declared under two names gets whichever principal ssh-keygen finds first.
- **F6 (LOW).** kernel/internal/cli/gitsign.go:61-67 — an existing `-git-ssh` file is accepted when only its `.pub` matches; the private file content is not checked, and a symlink at that path is followed by the git config. Check the private file against the key and refuse symlinks. `TestGitSignVerifies` skips when ssh-keygen is absent, so the hand-written key encoding is then untested.
- **F7 (LOW).** kernel/internal/cli/workspaces.go (agentNext) and workspaces_test.go — `YouMay` is always false regardless of who asks, and `TestUISealFlow` stubs `s.seal` and covers only the owner refusal over HTTP (the author, agent and signer refusals are covered only through `eligible`). `dos` ordering in `TestAgentNext` is a fixed string match, which is brittle but does fail on behaviour change.
