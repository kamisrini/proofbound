## Status
NEEDS_WORK: three MED, no HIGH. Checked and sound:
- Dispatch: `run()` reaches bundle mode only when `parseCommand` already returned `commandUI`, which requires `parseUI` to be valid, so `--bundle` with `--base`, a repeated flag, an unknown argument or a bad port is refused with usage (exit 2) before any bundle code runs. Bundle mode runs before `repositoryRoot()` and never opens a store, so it works outside a repository and ignores `DATABASE_URL`, as intended. `--trust-key`/`--repo` without `--bundle` are refused, so plain `ui` parses exactly as before; the only normal-mode changes are the link redirect target (still `/audit` when `bundle == nil`) and the `s.bundle == nil` conjunct on the agent read.
- Server: in bundle mode the switch answers only `GET /` and `GET /static/*`; every other path and every POST (after the unchanged cookie and Origin checks) is 404, so `/audit`, `/transcript`, `/agent/*` and `/act/*` are unreachable. The agent token is refused (401), no discovery file is written, the host check, CSP, nosniff, no-store and the HttpOnly SameSite=Strict cookie are the shared code. Unclean `/static/..` paths go to `http.FileServer` over the embedded FS, which rejects them.
- Parsing: `pbwarranty.Parse` is strict (duplicate keys, unknown fields, trailing data, non-canonical bodies refused), so the body the page renders is the body the signature covers, and `warrantyProof` re-canonicalizes the same raw body (identical to `f.canonical`); the Go re-check of the page's proof in TestBundleServer verifies. The browser verifier checks the `.sig` line's key equals `data-key` and verifies tag+bytes; it writes with `textContent` only.
- Labels: SIGNATURE ONLY is reached only through `ErrUnverified`, which `verifyThrough8` returns only after signature, cosignatures, rule and the trust-key pin all pass; a mismatched pin is INVALID. A SHA mismatch with the index downgrades to ALTERED even when the signature holds. MISSING/NO WARRANTY rows come from the index and say so. The trust-key state (pinned or not, with the out-of-band instruction) is in the head.
- File handling: index `file` values must match `^warranty-[0-9a-f]{12}\.json$`, so no traversal; symlinks, FIFOs, directories and other non-regular entries are refused by `Lstat` before any `Open`, so a FIFO cannot block start; reads are capped at 4 MiB; a missing, unreadable or wrong-schema `index.json` (or one whose base/head is not 40 hex) fails before serving.
- Escaping: every string reaches the page through `html/template` (attribute and text contexts, including the `data-*` proof attributes); TestBundleServer proves an index string with `<code>` is escaped.

## Findings
- **F1 (MED).** kernel/internal/cli/bundleview.go:219-233 with uikit/bundle.html:38-58. `checkWarranty` fills the issuer, change name, repository hint, reviewers, cosigners, promises (statements and verdict outcomes) and reviews from the body before, and regardless of, the signature check, and the template renders them for every row with a file, including INVALID ones. Confirmed: editing a warranty's statement to "System MUST do A, audited by Big4." gives `INVALID`, problem `signature`, and the forged promise table and reviewer list are still built and shown in the same layout as a real warranty. The same holds for a file signed by a key other than the pinned one. The spec says per-warranty content comes "from the signed body only"; a body whose signature fails, or that is signed by the wrong key, is not that. A reader skimming a hostile bundle reads forged promises next to a red tag whose only text is "signature". Fix: render body details only when the file's own check reached SIGNATURE ONLY, VALID or UNREVIEWED (keep them for ALTERED-but-signature-holds); otherwise show only the file name, key, result and problem, and word the bare "signature" problem as "the signature does not verify: this file's content is not shown". Add a test that an INVALID row carries no promises on the page.
- **F2 (MED).** kernel/internal/cli/bundleview.go:148-181 and :187-199. Nothing binds an index entry, its file name and the signed body to one commit, and duplicates are not detected. Confirmed: an index whose two entries (commits `12eb…` and `bbbb…`) both name the same genuine file gives two SIGNATURE ONLY cards for `12eb…` and the head count `SIGNATURE ONLY · 2`; commit `bbbb…`, which the index claims is warranted, silently disappears. The existing test itself shows `warranty-eeeeeeeeeeee.json` holding commit `12eb…`'s warranty reading SIGNATURE ONLY with only the generic "not in the index" note. So a hostile folder can inflate the green counts and make the file named for commit A carry commit B's warranty without the page noticing, which is exactly the "index pointing at another warranty's file" case the page exists to catch. Fix: mark a row ALTERED (or a distinct MISMATCH) when the parsed body's commit differs from the entry's `commit`, or when the file name is not `warranty-` + body commit[:12] + `.json` (index rows and extra files alike); treat a second entry naming an already-named file, or a second entry for the same commit, as ALTERED and count each file once. Add these three cases to TestBundleView.
- **F3 (MED).** uikit/bundle.html:6, :14, :17 and :22; bundleview.go:143. The page title and heading read "Warranties for `<base>..<head>`" and the head shows "Range", all taken from the unsigned index without a label, and nothing checks that a warranty's commit lies in that range, even with `--repo` (`VerifyReport` only checks that the clone's HEAD descends from the commit). A hostile bundle can present genuine warranties from an older release under a new release's range and read all green; the reader must compare hashes by hand to notice. The notice at :22 also says the page "uses the index only to notice files that are missing or altered", which is not true: the range, the NO WARRANTY rows, the waived list and the non-claiming count all come from it. Fix: label the range "from the unsigned index" in the heading and head (and make the title neutral, e.g. "Release evidence"), correct the :22 sentence, and with `--repo` check `base` is an ancestor of each commit and each commit an ancestor of `head` (marking a row "outside the index's range" otherwise); without `--repo`, say on each card that range membership was not checked.
- **F4 (LOW).** kernel/internal/cli/bundleview.go:108-126. `Lstat` then `os.Open` is a check-then-use race: if the folder changes between the two (a shared or synced folder), `Open` follows a symlink swapped in, or blocks forever on a FIFO swapped in; and `io.ReadAll(io.LimitReader(f, max+1))` returns max+1 bytes without error for a file that grew. Fix: `os.OpenFile(p, O_RDONLY|O_NOFOLLOW|O_NONBLOCK)`, check `f.Stat()` is regular and not over the cap, and reject `len(data) > bundleMaxFile` after the read.
- **F5 (LOW).** kernel/internal/cli/bundleview.go:148 and :183-199. There is no cap on the number of index entries or `warranty-*.json` files; each parsed file is held in memory with a base64 copy for the page, so a large hostile folder can exhaust the reader's memory before the server starts. Fix: cap entries and files (for example 10 000) or the total bytes read, and fail start with a clear message beyond it.
- **F6 (LOW).** uikit/bundle.html:25, :32 and :40. SIGNATURE ONLY uses `tag-passed`, the same green as VALID, in the counts and on each card, and without `--repo` the Reviewers line and the "SATISFIED (reviewer)" outcomes appear with no "not proven" mark (the head notice covers it, the card does not). The browser badge also reads green "verified in this browser" against the file's own key, whether or not the key is pinned. Fix: give SIGNATURE ONLY the `tag-disclosed` class, add "(not proven: no clone)" after the reviewers when `.Repo` is empty, and word the browser result "signature verifies for key <fp> in this browser" when the key is not pinned.
- **F7 (LOW).** kernel/internal/cli/bundleview.go:149-152 and uikit/bundle.html:31, :35, :71. Index strings are used unvalidated: an entry's `commit` (shown on MISSING and NO WARRANTY cards), the waived `commit`, and `reason` (shown as the card's problem text above the "unsigned index says" line). `short` cuts bytes, so a non-ASCII value can be split mid-rune, and the NO WARRANTY problem text is not itself labelled unsigned. Fix: require `sha40RE` for entry and waived commits (else ALTERED/omitted with a note), pass index strings through `printableUnit`, and put the reason inside the "the unsigned index says" sentence.
- **F8 (LOW).** kernel/internal/cli/bundleview_test.go:303-328 and :228-237. TestBundleRunsOutsideARepository skips (does not fail) when the binary cannot be built and in `-short`, and only reads the printed link; it never fetches the page, so a bundle server that starts but cannot render would pass. TestBundleView does not cover a symlinked `index.json` or the `--repo` UNREVIEWED path, and no test sets `DATABASE_URL` to prove it is ignored. Fix: fetch `/?k=…` then `/?format=json` from the started binary with `DATABASE_URL` set to an unusable value and assert a warranty row; fail on a build error; add the `index.json` symlink case.
