# P7 B1 unit-3 prepared-offline runtime fixture

This **proposed** change intent requests the owner's authorization for the governed `kernel/*` work
of P7 B1 unit 3, the prepared-offline runtime fixture scoped by
[`docs/plans/P7-postgres-b1-unit3-runtime-fixture-spec.md`](../../../plans/P7-postgres-b1-unit3-runtime-fixture-spec.md).
It implements `BR-replay-evidence-6e3d2b` O-1 by producing the runtime evidence the `internal/twin`
and `internal/twin/manifest` SPECs deliberately deferred (TWIN-INV-14 launched-binary witness; "real
PostgreSQL runtime fixtures and no-fetch witnesses remain pending"; case-manifest/behavior-lock
"cannot be rendered as a runtime `PASS`"). It is governed under the standing product-push
authorization ([[VD-agent-standing-authorization-5ouz7q]]); the owner remains the acceptor (Law 9)
and this record stays `proposed` until the owner accepts it — **no governed commit lands under it
while it is `proposed`.**

## Allowed scope

- Add a prepared-offline runtime fixture in `internal/twin` that drives the already-accepted
  `ReplayIsolatedWithVerifiedPostgres` seam against a verified, from-source minimal-permissive
  PostgreSQL archive supplied out-of-band (an environment-variable path; no baked path, no network,
  no ambient cache), producing a real `vera.replay.v1` proof over committed synthetic source/candidate
  fixtures (never presented as production observations).
- Add the runtime witnesses TWIN-INV-18..22 — launched-binary digest (closing the TWIN-INV-14
  deferral), zero-fetch, whole-ledger preservation, temporary-root cleanup, and real-proof binding —
  and extend `internal/twin/SPEC.md` (a SPEC.md edit, intent-exempt) to record them and their proving
  tests. The fixture uses a short Unix-socket directory (107-byte limit).
- Add a prep helper/procedure that packages the symlink-free `bin/`+`share/` subset of the accepted
  unit-2 build into a `.txz` and computes the committed archive manifest (archive SHA-256,
  `bin/postgres` SHA-256, sorted per-file inventory) for `VerifiedPostgresInput`. The archive bytes,
  any data directory, and any built executable are **never committed**.
- Author one `proofbound.p7.behavior-lock.v1` and one `proofbound.p7.case-manifest.v1` instance over
  the real proof so `EvaluateLock` derives `LOCKED` and `DeriveCaseStatus` folds to `PASS`, with the
  nine case outcomes carrying real evidence (witness records, command logs, produced artifacts).
- Commit only non-binary evidence (proof bytes, lock, case manifest, witness/command records) at one
  evidence revision; add deterministic synthetic tests; refresh the package-acceptance evidence
  (calibrated `make mutants`, every survivor declared) and prepare the independent non-author review
  packet.

## Explicit exclusions

This intent authorizes no new provider, event kind, external feed, writable truth, PostgreSQL route,
or snapshot provider (Gate 1 stays skipped); no change to the frozen `ReplayIsolated` subject, the
`vera.replay.v1` proof shape, or the authored/observed boundary; no redistribution of the built
binary and no committing of the archive bytes, data directory, or any executable; no network fetch,
ambient cache, or download fallback at replay time; and no `DEF-P7-001` activation or resolution.
Unit 3 produces runtime evidence; resolving `DEF-P7-001` and any redistribution go/no-go remain a
separate owner decision.

## Acceptance boundary

Acceptance requires this exact scope and native self-digest; the from-source archive to re-verify
against unit-1's source provenance before use; a real replay in which the launched `postgres` bytes
equal the declared digest, the run performs zero binary fetches, the source ledger is preserved
byte-for-byte, and the temporary root is removed on success and every failure path; `EvaluateLock`
== `LOCKED` and `DeriveCaseStatus` == `PASS` over the real proof; synthetic deterministic tests; a
calibrated package mutation sweep with every survivor declared; an independent non-author review of
the exact implementation revision and packet (Law 9); and the owner-listed repository checks
(`make check` green). The owner remains the final acceptor. Producing runtime `PASS` evidence does
not by itself resolve `DEF-P7-001`.
