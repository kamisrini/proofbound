# R2 polish: `sync all` reads specs when a profile is committed; `review seal` takes draft.json too

**ACCEPTED by the owner 2026-11-19** ("before you tag lets do the 2 fixes and then tag"; recorded by
the agent as scribe). The two rough edges in the warranted-commit workflow (`BR-sdd-warranty-i9miv7`
O-8) that the R2 docs audit found: users had to remember `sync intent sdd` before `sync all`, and
`review seal` rejected the `draft.json` path that `review draft` prints.

## Allowed scope
1. `cli`: `sync all` also runs the `sdd` intent sync, after records/specdir and before git, when HEAD
   has a committed `.proofbound/sdd-profile.json`. Without one, `sync all` is unchanged. `sync intent
   all`, `verify` and their provider sets are unchanged (SDD-INV-56 amended, CLI-INV-23).
2. `cli`: `review seal` accepts the draft folder or its `draft.json` (CLI-INV-24).
3. The sdd M3 interleaving test drives its hold/refusal via `sync git` + `sync reviews`, since
   `sync all` now ledgers the specs itself.
4. Docs and the AGENTS block: `proofbound sync all` alone is enough on a project with a profile.

## Explicit exclusions
- No change to the sdd provider, the ledger write path, the readiness decision, or event kinds.

## Acceptance boundary
`make check` green, the R2 demos re-run, and one non-author review of the code (Law 11 budget).
