# Make the p6-task1-close README phase-status assertion track Release 1, not stale P6 prose

**ACCEPTED under standing authorization** ([[VD-agent-standing-authorization-5ouz7q]]; owner is the
non-author acceptor, Law 9). Implements [[BR-gate-integrity-4b2e08]] obligation **O-1**: the
acceptance gate (`make check`) must be a trustworthy, non-brittle witness.

`scripts/p6-task1-close.sh` (the C1-001 census closure check) hard-coded the exact README sentence
`Current project status: P6 complete; P7 planning only.`. When the README was legitimately refreshed
for Release 1, that stale assertion failed `hooks-test` — a gate failing on a *correct* content
update is a gate-integrity defect (`LESSON class=hardcoded-fixture-coupling`). This change retargets
the assertion to a stable Release-1 phrase so the gate verifies the README still states a phase
status without pinning a sentence that must change every phase.

## Allowed scope
- `scripts/p6-task1-close.sh`: replace the single hard-coded phase-status string the C1-001 check
  requires in `README.md` with the stable Release-1 phrase `feature-complete and independently
  accepted` (still a phase-status assertion; no change to the C1/C2 census counts or any other check).

## Explicit exclusions
- No change to census row counts, gate rows, or any other hook assertion.
- No change to kernel code, projections, or the ledger.

## Acceptance boundary
`make check` green and deterministic; the C1-001 assertion passes against the Release-1 README and
would still fail if the README dropped its phase-status statement. Governed commit lands with an
`Intent: CI-readme-r1-status-b7f2a9` trailer and `Authorized-By: Srinivas Kamisetty`.
