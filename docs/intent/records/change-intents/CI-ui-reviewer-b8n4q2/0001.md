# A reviewer does the whole review in the browser

**ACCEPTED by the owner 2026-11-25** ("reviewers should be able to do their activities in UI", then
"lets do both r1 and r2"). Implements [[BR-audit-room-ui-r7t3w1]] O-8 (the Review bench runs declared
tests and takes their decisions; flags on each line), O-7 (the Changes page; Issue the warranty) and
O-5 (the verify page). Design: [ui-reviewer-spec.md](../../../../plans/ui-reviewer-spec.md).

## Allowed scope
`kernel/internal/cli` (bench, change, workspaces, ui, starter's seal split, tests' progress and
environment, bundle's compute split, templates and script), `kernel/cmd/proofbound-verify` (new),
`kernel/internal/store` (a browser-only lock stub), `scripts/release-build.sh` and its test, the
CLI-INV-47, 67, 75..79 rows, and docs.

## Explicit exclusions
No change to what `review seal` writes, signs or decides, to `check`, to the warranty format or rule,
or to what `warranty bundle` writes; no hosted service; no new dependency (the WebAssembly build uses
the Go toolchain).

## Acceptance boundary
`make check` green, a mutation check with calibration controls, one non-author code review per part,
and the live demo's review steps giving the same result through the browser as through the CLI.
