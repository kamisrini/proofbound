# VD-stack-go-fid9mi: Go all the way — kernel, CLI, connectors

**Status:** Accepted
**Date:** 2026-08-07
**Context:** Stack choice for the P1 Flight Recorder kernel. Requirements: boring and long-lived (this is infrastructure, not an app), single-binary distribution (a control plane should install as one file), a language whose idiom the founder can personally review 100% of, and a test story that runs with no daemons so `make check` stays fast for clone-and-run.
**Decision:** `kernel/` is a single Go module (Go ≥1.26, `toolchain` directive pinned): `cmd/vera/` (CLI) + `internal/{core, store, connector/git, connector/checks, connector/sessions, projections}`. Database: Postgres via **pgx/v5**; dev/test uses **fergusstrange/embedded-postgres** (a real PG binary as a child process against `.vera/db/`, daemon-free) with a `DATABASE_URL` escape hatch for a server. Migrations: **pressly/goose** over `embed.FS` SQL files (ledger schema only; projection DDL stays derived, outside the migration stream). IDs: **oklog/ulid/v2**. Canonical JSON: **gowebpki/jcs** (RFC 8785). CLI args: stdlib `flag` + subcommand switch (zero-dep; revisit a framework only if the CLI grows). Tests: stdlib `go test` (table-driven, fakes not mocks); lint: **golangci-lint** (required prereq). This record is also the P1 baseline-dependency blessing: pgx/v5, embedded-postgres, goose, ulid, jcs — any dependency beyond this set needs its own VD before install. Web UI language deferred to P3+ (no UI before then).
**Consequences:** One language across kernel and future services; a single-binary `vera`; code the founder can review idiomatically end to end. Gives up: in-process database lightness — embedded-postgres spawns a real PG per command (~1–2s startup, accepted) — and the schema-validation sugar of dynamically typed ecosystems (Go structs plus explicit validation instead). The single-data-dir constraint is load-bearing: two processes must never open `.vera/db/` concurrently, which is why every CLI command takes the lock described in the P1 plan.
**Revisit when:** the kernel needs an embedded UI story (P3+), or embedded-postgres startup cost pushes `make check` past ~30s.
