# VD-verdicts-are-artifacts-rl0rab: a verification verdict is committed to the repo on receipt, verbatim

**Status:** Accepted
**Date:** 2026-08-14
**Context:** The cost of NOT doing this was paid three times in two days. Round 1's and round 2's adjudication verdicts lived only in workflow transcripts outside the repo; both were flagged as "brittle" in the resume note twice, and both had to be reconstructed from journal summaries whenever a later session needed the exact wording — the round-2 fix list was re-typed into `state.md` by hand, which is how a REVIEWER'S wrong remedy nearly got applied verbatim (VD-verification-asymmetry-2dyjnd point 2 exists partly because the primary text was not at hand to re-read). Round 3 was then lost outright: the session hosting it shut down mid-adjudication, and only a salvage pass against the transcript directory recovered the three completed lens reports. The repo's own thesis — an append-only ledger of what actually happened — was not being applied to the most expensive evidence the project produces: a full adversarial round costs ~1M subagent tokens, and its verdict was the single artifact kept OUTSIDE durability. Meanwhile the machinery for keeping it honest already exists in-repo: `cleanroom-lint` scans anything tracked (and did catch a confidential path in a note at session end), `link-lint` refuses id-shaped strings that cite nothing, and `figure-provenance` polices unaccompanied figures.
**Decision:** Every adversarial-round adjudication is committed under `docs/verification/verdicts/<round>-adjudication.md` in the same session it is received — verbatim, with a provenance header naming the run id, the driving script, and the HEAD under review. Raw lens reports are NOT committed: the adjudicator's job is to discard their unproven claims, and committing the raws would enshrine what was discarded (they remain recoverable in the run transcript, whose `journal.jsonl` holds every completed agent's return — the round-3 salvage worked exactly this way). If the tree moved between dispatch and receipt, the header says what changed, because a verdict is evidence about a specific HEAD and silence about drift converts it into evidence about nothing. Retroactively applied: rounds 1 and 2 were salvaged from their surviving run journals and committed under this rule on 2026-08-14.
**Consequences:** Verdicts become citable by path instead of re-typed from memory, and `cleanroom-lint`/`link-lint` now police their content the moment they land — which matters, since adjudications quote file paths and identifiers by design. The repo grows ~25k characters per round; accepted, the ledger thesis does not get to have a size exemption for its own evidence. A verdict that is itself wrong gets committed too — committing records receipt, not endorsement, and the round-2 verdict already demonstrates both (its findings held; its proposed remedy for HIGH-3 did not).
**Amended 2026-08-14 (same day, mechanics only — the decision stands):** "verbatim" yields to the
cleanroom boundary, which is absolute. The first committed verdicts carried absolute filesystem paths
containing a personal username, and `cleanroom-lint` refused them — one commit late, because it scans
TRACKED content and the files were invisible until the commit landed (a staged-content scan is the
recorded residue). Verdicts are therefore committed verbatim EXCEPT for mechanical redaction of
cleanroom-forbidden strings (absolute paths, usernames), each redaction marked in the provenance
header with its replacement token and count so a reader knows exactly what changed and how much. The
technical content is untouched; an unmarked redaction would be an edit, which this record still
forbids.

**Revisit when:** verdicts grow beyond ~100k characters each (consider committing a structured summary plus the full text compressed); or the workflow runtime gains first-class durable outputs that survive session death (the salvage half of this record becomes redundant, the commit half does not).
