# VD-local-only-backup-mjic4a: local-only git for now; bundles are the backup mechanism

**Status:** Accepted
**Date:** 2026-08-08
**Context:** The repo has no remote and the maintainer has chosen to keep it local for the foreseeable future (publishing is a separate decision, deliberately deferred). The existing backup advisory in docs/gates.md named "replace with a private remote" as its graduation path with an expiry of 2026-08-21 — a path we are now choosing not to take. Under Build Law 4 an advisory must graduate or be deleted; letting it silently expire, or re-dating it without stating why, is precisely the drift the law exists to prevent.
**Decision:** No remote for now. Off-machine durability is provided by `make backup` (a `git bundle --all` written to `~/Backups/`), run at the end of any session that produced commits. The gates.md row is re-stated to match reality: its graduation condition is no longer "add a remote" but "make the bundle cadence mechanical" (a `make check` freshness assertion on the newest bundle, or a scheduled job), with a new expiry of 2026-10-16 aligned to the P2 window. Publishing to a remote remains available at any time and needs no new decision — but adding one supersedes this record's backup rationale, so record it then.
**Consequences:** Zero publication risk while the design is still moving, and no dependency on network or account setup during P1. Accepted cost: a single-machine failure loses everything since the last bundle, so the bundle discipline is the real control — an untested backup is not a backup, so the first bundle is verified by cloning from it. P1 Task 0.1 stops being an interactive blocker; the P1 executor can run Task 0 end-to-end without human input.
**Revisit when:** a second contributor joins, publication is chosen, or two consecutive sessions end without a bundle (the discipline is not holding and the cadence must become mechanical immediately).
