# VD-review-ceremony-tiers-v2b6kp: review ceremony is tiered by package class, and the parallel round comes EARLY

**Status:** Accepted
**Date:** 2026-08-10
**Context:** Task 3 (`kernel/internal/store`) cost seven review rounds and roughly 3.3M tokens across two days. Every round found real defects, so no round was wasted — but the rounds were not equal. The six SEQUENTIAL single-reviewer rounds (~250k tokens each) found record defects, vacuous assertions, and proof-accuracy errors. The ONE parallel multi-lens round (~1.8M tokens: mutation-adequacy · spec-truth · concurrency · build-laws, plus an adjudicator that discarded eight unproven claims) was the only round that found a live concurrency bug (H1: `flock` refusing a lock nobody holds during a `fork` window, reachable in ordinary operation) and the only one that falsified the survivor count by running calibration controls. It ran LAST, so the worst defect was found last — after six rounds had already declared narrower verdicts.
**Decision:** Ceremony is tiered by package class, and the heavy instrument runs EARLY rather than last.
- **Foundational packages** — those where a defect becomes unreachable or is inherited by everything downstream (`internal/core`, `internal/store`, and any future package owning identity, ordering, locking, or crash semantics): spec-first → build → **ONE instrumented parallel multi-lens round**, run as the FIRST verification rather than after a series of sequential passes. Instrumented means: calibration controls before any mutation count is believed (a positive control that must die, a neutral control that must survive), path-guard mutations re-run under a realpath'd `$TMPDIR`, and an adjudicator that discards any finding without a reproducible proof.
- **Connector / peripheral packages** — I/O-shaped, failures surface immediately, defects are not inherited (`internal/connector/*`, `internal/projections`, `cmd/vera`): spec-first → build → **one adversarial review**. Escalate to the foundational tier the moment the work touches concurrency, filesystem identity, crash safety, or the ledger's write path.
**Consequences:** The instrument that demonstrably finds live bugs is spent where it pays, and we stop paying ~250k tokens per sequential round for passes that mostly found record defects. Accepted cost, stated plainly: **the lighter connector tier is a bet, not a measurement** — we have no connector defect data yet, and `store` looked like "just a database wrapper" at spec time, which is precisely the misread H1 hid behind. The escalation trigger is therefore a judgement made before the risky code is fully understood, and it will sometimes be made wrong. Mitigation: the first connector (Task 4, git) runs the light tier and its outcome is measured against this record — if its single review finds a defect class the sequential rounds would have caught, the tier boundary moves.
**Revisit when:** Task 4 (git connector) completes its light-tier review — compare what it found against Task 3's round-by-round yield; or any connector defect reaches P2; or a foundational package passes its single parallel round and a later round still finds a HIGH (which would mean one round is not enough even instrumented).
