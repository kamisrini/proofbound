# PART 1 — WHAT VERA IS (identity, non-negotiable)

**VERA** (*Latin: true things*) is a greenfield, category-creating trust layer for AI-built software. Its design laws are inversions of well-known failure modes in process-and-policy tooling generally: enforcement that decays silently, duplicated sources of truth, warnings that never become errors, and unmeasured tool-maintenance cost. **Past failure is evidence, never architecture** — when a design feels like a reaction to a past failure, ask what a system with no memory of that failure would do. This project is an imagination exercise as much as an implementation.

**★ THE NORTH STAR (founder-ratified, record it verbatim):** *"This is our north star, this is our greatness, this is our goal. This is our guiding principle till we are done. Aim high, go big go home."* — ratifying this vision: **software stops being an artifact you possess and becomes a promise the world keeps.** Only three things persist: **intent, meaning, and memory**. The 100x vision sets DIRECTION; the 10x vision sets PACE; every phase review asks both *"did we build what we planned?"* and *"did we imagine hard enough?"* The 100x may invalidate 10x decisions via a recorded decision — joyfully, never defensively.

**Elevator pitch:** By 2028, AI writes the world's software — and no one can prove any of it is safe. VERA is the trust layer for that world: it records what agents actually did (Flight Recorder), simulates every change before reality touches it (Living Twin), and ships every system with a machine-checkable warranty (Trust Engine) — who built it, who verified it, who answers when it fails — governed by an executable constitution (Governor) where humans do judgment only, minutes a day. Code became free; we sell certainty. **Mission:** make trusting software a fact, not a faith. **North-star 2030:** no software ships without its warranty. **Testing becomes 100% redundant as a human activity, 0% redundant as physics** (proofs can't validate intent; the world has no spec — evidence becomes ambient, never authored).

**Architecture (2028):** a kernel + four organs. Kernel = **THE FLIGHT RECORDER**: append-only event ledger (one write path — observed events from connectors, never hand-written), signed re-executable witnesses, content-addressed claims/evidence (no caller-supplied pass booleans, ever), rebuildable projections, gates-as-data. Organs: **Intent Fabric** (what should be true: behavior locks, disambiguation ledger, consequence briefs replace PRs, divergence ledger replaces backlogs), **Living Twin** (what would happen: ephemeral replay universes, learned OOD-honest surrogates, invariant ledger replaces test cases, incident precognition, public calibration), **Trust Engine** (what is provably true: verifier fleets with keys cryptographically disjoint from builders, adversarial bounty economy, compliance compiles to queries, trust decays without fresh evidence, portable warranties — the business), **Governor** (programmable org: constitution kernel, decision router, portfolio optimizer, trust ratchet). Agent fleets are commodity — orchestrated, never trusted, behind an action gateway (scoped ephemeral credentials, taint tracking, co-signing). Build phases: P1 kernel → P2 gates → P3 external connectors → P4 twin.

**The empirical premise, earned in this repo's first fortnight and binding on the product (record it as VD-verification-asymmetry):** finding defects converges — every adversarial round productive; fixing them does not — remediation introduced defects at roughly the fix rate, and being MORE careful changed nothing. The only lever that has ever moved the rate is MECHANISM: script-plus-self-test lesson classes recurred zero times against 3–5× for prose. Corollaries, all measured: a verified FINDING transfers zero verification to its proposed FIX (a reviewer's remedy was wrong; the author's replacement remedy was also wrong, on the half of the corpus he did not check); a claim of "verified against X" is a claim about ALL of X and must be a loop over X, never an enumeration from memory; claims are stated as HARMS/invariants, never reproductions (fixing the reproduction while the invariant stays false was the single most common repair defect); every "cannot / never / always" in a comment is a test or a defect (two were false in one package in one week, both load-bearing); evidence keyed to POSITION (line numbers, ordinals) expires silently — evidence keyed to CONTENT (content_sha) expires loudly.

# PART 2 — THE TEN BUILD LAWS (this repo runs under them; enforce mechanically)

**Law numbers are PERMANENT identifiers: new laws APPEND; none is inserted, re-ordered, re-used or silently retitled.** The same rule binds SPEC invariant IDs. Both namespaces are pinned in `@generated` locks (`docs/laws.lock`, `docs/invariants.lock`) checked by blocking lints — regenerate a lock ONLY on a deliberate append/retitle; the lock DIFF is the review (an insertion shows as many changed titles, an append as one line). This rule was broken twice by the author WHILE enforcing it — knowing a rule is not the same as being unable to break it, which is why both detectors exist.

1. **Derived state or dead state** — generated artifacts carry `@generated` + regeneration command, are blocked from hand-edits by an edit-time guard where the harness provides one, and `make check` fails if regeneration diffs (the harness-independent backstop). Corollary learned: a guard whose deletion changes nothing is dead state too — delete it, don't comment it (a comment explaining a dead guard's purpose makes it read as load-bearing).
2. **One home per datum** — a fact stored twice is a drift seed; link, never copy. For the resume note this is also an EDITING rule: overwrite-in-place means full rewrite, never patch — regex surgery on it produced a self-contradictory note within hours of Law 10 landing.
3. **Enforcement proves it fires** — every hook/gate has self-test cases run by `make hooks-test` inside `make check`; blocking checks FAIL CLOSED on missing dependencies. Three extensions, each earned: (a) every scanning gate carries an INERT-DETECTOR guard — empty input or a pattern matching nothing is an ERROR, never "clean" (two gates historically reported success while checking nothing); (b) calibration controls must span INDEPENDENT failure dimensions — two controls that both resolve through the compiler cannot tell "tests ran" from "tests silently did not"; (c) a gate's SCOPE is as load-bearing as its logic — scope bugs are silent by construction (a one-level glob left every connector SPEC unread while printing clean).
4. **Nothing advisory without an ISO expiry + owner** — registered in docs/gates.md; a DATELESS advisory row fails the build; an EXPIRED one fails the build (graduate or delete).
5. **Meta-tax budgeted** — `make meta-tax` measures scaffolding-only commits; budget ≤25% bootstrap / ≤10% steady, home = gates.md. (Measured 12% during the heaviest gate-building fortnight — the budget held.)
6. **Spec before code** — every kernel package gets SPEC.md with a machine-parseable invariant table `| INV-n | statement | test_file::TestName |` before implementation. § 2 is a mechanical INTERFACE LOCK: a per-package speclock test compares § 2's declared names AND struct fields against the AST (names alone left `Result.Cursor` deletable with every gate green). One SPEC governs one package — a child package that grows decisions of its own earns its own SPEC (the "thin translation layer, no decisions" justification was self-fulfilling: the untested child held four HIGH defects).
7. **Lessons compile to enforcement** — journal mistakes with a greppable `LESSON[tag]:` prefix; a class seen twice MUST become a hook case/gate row/spec invariant/law amendment or be explicitly retired. Tags come from the registry `docs/lesson-classes.txt` (six parent classes; an unregistered tag fails the build) — free-text tags let the same class hide under fresh names, which defeated the recurrence counter for two days.
8. **Small kernel, boring tech: Go all the way** — Go ≥1.26 + Postgres. Baseline blessed deps: pgx/v5, fergusstrange/embedded-postgres, pressly/goose, oklog/ulid/v2, gowebpki/jcs, stdlib flag. ANY dep beyond this set needs a decision record BEFORE `go get`. Go conventions: standard library first; constructor-injected dependencies via a config struct; small interfaces declared where they are consumed; errors wrapped with %w and checked with errors.Is; contexts first-argument; table-driven tests with hand-rolled fakes.
9. **No actor grades its own work** — the author of a change may fix it; only a verifier who did not write it may accept it. The evidence: nine adversarial rounds on the first package, nine non-empty verdicts; the author — under explicit rules about not trusting himself — shipped a test that could not fail in the same session he was fixing tests that could not fail. Corollary: a verdict is only as good as its harness, so a mutation sweep states its calibration controls (a positive that must die, a neutral that must survive, and a LETHAL injected-failing-test control proving the test step actually runs) before its count is believed.
10. **The resume note is live state** — `notes/state.md` is rewritten (never patched) every ≤3 commits, gate-enforced; `make state` prints the derived half so compliance is cheap. A note updated only at session end described a repository two days gone to the one reader who needed it most.
